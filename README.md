# 🚀 Creator-Flow
> 창작의 수익을 돕는 굿즈 제작 가이드

<br>

## 📌 1. 프로젝트 개요 (Overview)

### 👥 주요 타겟 (Target Audience)
- **주요 타겟**: 굿즈 제작을 본업이나 취미로 하는 모든 창작자
- **고객 특성**: 자신의 캐릭터를 활용한 장기적 (자체 브랜드 비즈니스)와 유행 주기가 빠른 팬아트/2차 창작 모델을 동시에 운영하는 창작자. 디자인부터 발주, 유통 채널 관리(온·오프라인), 정산까지 모든 공정을 책임지는 제조 기업의 형태와 유사.

### 💡 기획 배경 (Background)
크리에이터 이코노미의 급격한 성장으로 1인 창작자가 늘어가고 있지만, 이들이 마주하는 제조 및 유통 비즈니스 로직은 파편화되어 있다.
1. **유통 수수료로 인한 이익의 착시**: 홍대 소품샵 등 오프라인 입점처와 자체 온라인 통판의 극심한 채널별 수수료 격차를 고려하지 않고 단순히 [원가+희망마진]으로 가격을 책정했다가 정산 시 적자를 보는 리스크가 존재.
2. **원가 계산에서의 고정비 누락**: 스티커 뒷대지, 포장용 OPP 비닐 등 제품 하나를 완성하기 위해 들어가는 미세 부자재 비용이 계산에서 누락되어 실질 마진이 붕괴되는 현상이 발생.
3. **발주 수량 결정 장애**: 비지니스적 판매와 단순 취미 및 팬아트라는 사업 모델별 특성이 다름에도 불구하고, 제조 업체마다 제각각인 수량별 단가 하락 조건을 비교할 정량적 기준이 없어 발주 피로감이 극심.

Creator-Flow는 이러한 창작자들의 공학적 계산과 공정 관리 리스크를 IT 솔루션으로 해결하여, 창작자가 오롯이 '디자인'에만 집중할 수 있는 환경을 제공하고자 시작되었습니다.

<br>

## ⚙️ 2. 핵심 기능 (Key Features)

### 🧮 30초 완성 역산형 정가 계산기
- **실질 마진 완벽 방어**: 창작자가 최종적으로 손에 쥐고 싶어 하는 '목표 순이익'을 먼저 입력하면, 플랫폼별 수수료 프리셋과 숨은 고정비(포장재, 부자재 원가)를 역으로 계산하여 실질 순이익을 완벽하게 보장하는 최적의 정가를 도출.

### 📊 BUSINESS / FAN-ART 맞춤형 제작 시뮬레이터
- **모델별 맞춤형 분석**:
  - **Business Model**: 지속적이고 안정적인 수익 구조를 지향하는 모델. 초기 재고 확보 부담을 고려하더라도 대량 생산을 통해 생산 단가를 낮추고, 장기적으로 안정적인 마진을 확립하기 위한 자산 최적화 시뮬레이션을 지원.
  - **FAN-ART**: 취미나 2차 창작 등을 위한 모델. 과도한 재고 리스크를 최소화하는 동시에, 소량 발주 시 상승하는 원가 사이에서 균형을 잡아 가장 안전한 제작 지원.
- **원스톱 프로젝트 생성 및 페이지 연동**: 시뮬레이션을 통해 도출된 최적의 발주 수량, 단가, 예상 고정비 데이터는 휘발되지 않고 클릭 한 번으로 **즉시 정식 프로젝트 생성**으로 이어집니다. 생성된 데이터는 **프로젝트 관리 페이지와 실시간으로 연동**되어, 해당 굿즈가 디자인-발주-판매-정산 공정으로 매끄럽게 이어지도록 유기적인 파이프라인을 형성합니다.

### 📦 5단계 공정 기반 프로젝트 관리 시스템
- **창작 파이프라인 시각화**: 디자인 - 발주 - 협업 - 판매 - 정산으로 이어지는 복잡한 굿즈 제작 사이클을 한눈에 모니터링할 수 있는 대시보드를 제공.
- **단가 및 손익분기점(BEP) 시각화**: 시뮬레이션을 통해 입력된 데이터로 굿즈 프로젝트 제작 차수별로 단가 및 손익분기점 그래프 기록.
- **이미지 중심의 차수별 데이터 아카이빙**: 수십 종의 굿즈를 이미지 기반으로 직관적으로 분류하며, 동일 굿즈의 제작 차수(1차 제작분, 2차 재판분)별로 달라지는 원가와 재고 흐름을 꼬임 없이 정교하게 기록하고 추적.

## 🛠 3. 기술 스택 (Tech Stack)

### 🎨 Design
- **Figma**: 컴포넌트 기반 UI/UX 디자인 및 디자인 시스템 설계

### 💻 Frontend
- **Kotlin & Android Studio**: 안드로이드 네이티브 환경 최적화 및 디버깅
- **UI/UX 구현 관점**: 복잡한 역산 수식과 계단식 비교 테이블을 사용자가 직관적으로 인지할 수 있도록 시각적 피드백 중심의 컴포넌트를 설계했으며, 프론트엔드 코드에서 구조적으로 컴포넌트화하기 수월한 인터페이스를 구축했습니다.

### 🗄 Backend
- **PYTHON/Fast API**: API 설계
- **Database (MySQL)**: 굿즈 데이터베이스 구축
- **데이터 구조화 관점**: 다품종 굿즈의 차수별 원가 변동, 재고 흐름, 채널별 수수료 데이터가 화면단과 오차 없이 유연하게 연동될 수 있도록 체계적인 데이터 구조를 설계했습니다.
